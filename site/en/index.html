Good metrics are not
the same as trust.

Ports, identifiers, target columns, and temporal splits can all leak the answer into the feature matrix. FlowLab checks for the things that inflate metrics before training starts. Split, leakage, ablation, and sample size all feed the same final verdict.

  • Labels never enter featuresLabel and identifier columns are dropped before training.
  • Preprocessing is fitted on training data onlyTest-set statistics never leak backward.
  • Same data and seed reproduce the experimentMetrics and the experiment fingerprint stay stable; reports include a generation time.

Not a dashboard.
A lab ledger.

Every judgment can be traced back to data, features, and parameters, without relying on a polished overview chart.

Setup
Data source, temporal/random/entity split, validation and test sizes, seed, models, threshold policy, and ablation column. Validation selects the model; test is reported once.
Evidence
Validation/test AUC, PR-AUC, F1, false-positive rate, confusion matrix, score curve, threshold sweep, ROC/PR and calibration curves, label quality, class distribution, exact feature list, and runtime environment.
Verdict
The verdict card, checklist, and warning badges share one source of truth. Cross-experiment comparison audits the data, features, split, and validation size before comparing numbers.
Next step
Rerun without a leaking column, test an ablation, inspect the most suspicious flows, investigate by attack type and source IP, or export HTML / Markdown / JSON / CSV.

Four steps from experiment to evidence.

Every step has explicit inputs and outputs. Someone else can rerun it from the command and dataset fingerprint.

  1. 01

    Ingest

    CSV, pcap, Zeek conn.log, parquet, npz, Excel, and other formats: 14 entry points in total.

    flowlab run flows.csv
  2. 02

    Audit

    Check identifier, port, target, duplicate-row, entity-overlap, and temporal leakage introduced by random splits.

    --ablate dst_port
  3. 03

    Compare

    MLP, Isolation Forest, and AutoEncoder share one feature matrix; validation selects the model, test reports the score, and historical runs can be checked for comparability.

    --models mlp,iforest,autoencoder
  4. 04

    Archive

    The report records dataset fingerprint, seed, split, threshold source, validation/test metrics, features, and suspicious flows.

    --html out/report.html

A report is more than screenshots.

One payload drives the Web UI, Markdown, and standalone HTML. Whoever receives the report can see why the verdict holds and rerun the experiment from the fingerprint and command. It also includes PR-AUC, per-class recall, and representative false positives and misses. The sample report is currently generated in Chinese.

Run local.
Keep the data local.

The Web workbench is served by a local Python process. Reports and experiment history stay on the machine. GitHub Pages hosts only this introduction and a static sample report generated from synthetic data.
