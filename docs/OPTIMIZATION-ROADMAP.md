# FlowLab 优化路线图

> 目标不是把所有异常检测功能都塞进一个界面，而是让每一次实验更可信、更容易复查、
> 更适合交给别人复现。下面按优先级列出下一步最值得做的事，每项都给出验收标准。

## 当前基线（v0.6.0）

已经完成的能力：

- 统一数据入口：CSV、pcap、Zeek、parquet、NumPy、Excel、JSON 等；
- 数据审计：标签/标识符/目标/端口/时间切分检查，端口泄漏可联动消融；
- 评估：AUC、PR-AUC、F1、精确率、召回率、误报率、混淆矩阵；
- 调查：按攻击类型召回与误报率、典型 FP/FN、源 IP 告警排序；
- 复现：数据指纹、实验指纹、种子、切分、特征清单、来源与复现命令；
- 交付：本地 Web、移动端抽屉、Markdown/HTML 报告、wheel、Docker；
- 质量门禁：125 个后端测试、11 个前端测试、Ruff、npm 全量审计、wheel 与 Docker CI。

以下不再列为“待优化项”，除非出现回归：标签完整性拒绝、时间切分退化标记、
训练集专用预处理、移动端配置/历史/报告三个入口。

## 方法学底线：在扩功能之前先解决

### A. 测试集只用于最终报告，不参与模型选择

**问题**：当前界面用测试集 AUC 选出“最佳模型”，再把这个模型的测试指标放在首屏。
如果测试集同时承担“选模型”和“报成绩”，结果会系统性偏乐观。

**建议**：

- 从训练集再切出验证集；模型、阈值和超参数只在验证集上选择；
- 测试集只在最后评估一次，报告中明确写“选择集”和“报告集”；
- 数据不足时使用固定种子的交叉验证，但时间序列必须用时间块/滚动验证；
- `best_model` 改名为“验证集最佳”，同时保留每个模型的测试指标供对照；
- 实验指纹加入选择规则，避免两次实验因选择方式不同却看起来相同。

**验收标准**：

- 不读取测试标签也能完成模型和阈值选择；
- 报告明确区分验证指标与测试指标；
- 同一数据、同一选择规则可稳定复现最终模型。

### B. 切分时检查重复与实体重叠

**问题**：完全重复的流、同一会话被拆成多条流、同一源 IP 的相邻时间窗，
都可能同时出现在训练集和测试集。行级切分无法识别这种“实体泄漏”，
即使 AUC 很高也不能证明模型能泛化到新主机或新会话。

**建议**：

- 计算内容重复率，并统计跨训练/测试的重复行；
- 支持按 `flow_id`、五元组或 `src_ip + 时间桶` 分组切分；
- 报告中分别列出“随机行切分”和“按实体分组切分”的结果；
- 对时间切分检查同一长连接是否跨越切分边界。

**验收标准**：

- 存在跨集重复时明确警告，且可一键切换分组切分；
- 分组切分保证同一实体不会同时出现在训练和测试；
- 报告说明当前指标对应哪种泛化场景。

## P0：下一到两个版本

### 1. 跨实验对比视图

**问题**：现在历史记录只能逐条打开，无法在同一屏比较“修泄漏前/后”或不同阈值。

**建议**：

- 历史列表支持多选 2–4 次实验；
- 先校验数据指纹与特征矩阵是否一致，不一致时明确标红而不是直接比数字；
- 同表展示 AUC、PR-AUC、F1、FPR、召回率、阈值、切分方式、耗时；
- 支持导出对比表为 Markdown，写进论文附录；
- 新增 CLI `flowlab compare` 的同构 JSON 输出，前端与报告共用同一结构。

**验收标准**：

- 两次同数据、不同阈值的实验能在一屏看出 FPR/召回率变化；
- 数据指纹不同的实验会显示不可比警告；
- 对比结果有单元测试与一份可离线打开的 HTML/Markdown 示例。

### 2. 长任务进度与取消

**问题**：69 万行数据上 MLP 可能需要数分钟；当前只有“运行中”，用户不知道进度，
刷新页面也看不到任务是否还在运行。

**建议**：

- 为“读入 → 特征 → 模型 1/N → 消融 → 报告”定义阶段事件；
- API 返回 job id，前端轮询或使用 Server-Sent Events 接收阶段进度；
- 支持取消尚未开始的模型和后续消融；已进入 sklearn 的训练不必强杀线程；
- 离开页面前提示“实验仍在运行”；
- 限制同时运行的任务数，避免上传多个大文件把本机内存打满。

**验收标准**：

- 前端能看到当前阶段、已完成模型数和预计剩余阶段；
- 取消后不会写入不完整历史；
- 同一进程内最多运行一个重型实验，第二个请求返回明确的排队状态。

### 3. 历史库检索、容量与迁移

**问题**：整份 payload 都存在 SQLite 中，历史越多数据库越大；目前没有搜索、标签、
按模型筛选，也没有显式的 schema 版本。

**建议**：

- 为 runs 增加 schema version、experiment fingerprint、模型列表、标签和备注；
- 历史页支持按来源/数据指纹/模型/日期筛选；
- 支持给实验加备注和“基准/失败/已归档”状态；
- 增加配置化的保留策略（按条数或天数），并给出数据库体积；
- 写迁移函数，旧记录读不出来时给出升级提示，而不是让页面报 500。

**验收标准**：

- 旧版数据库能自动迁移或给出可操作提示；
- 搜索 1000 条历史记录仍在 200 ms 内返回；
- 删除和保留策略有测试，不会误删当前打开的实验。

### 4. 阈值扫描、PR 曲线与校准

**问题**：当前阈值是手动滑杆，无法快速看到不同阈值下的 FPR/召回率权衡，也没有概率校准。

**建议**：

- 对最优模型输出 PR/ROC 曲线和阈值扫描表；
- 允许按目标 FPR 自动选阈值，并记录选择规则；
- 提供 calibration curve 与 Brier score，提醒“分数不是概率”；
- 报告明确区分“排序指标”和“部署阈值”。
- 把当前的 CICIDS 启发式区间做成可配置的数据集画象；未知数据集只提示异常，
  不直接给出“可用/不可用”的强判断。

**验收标准**：

- 用户能在一次运行后看到 10–20 个阈值点的 FPR/召回率；
- 自动阈值会写进复现配置和实验指纹；
- 报告明确指出阈值来自数据驱动还是人工指定。

### 5. 标签质量仪表盘

**问题**：标签缺失已经会被拒绝，但重复流、五元组冲突、攻击类型极不均衡仍只看得到总数。

**建议**：

- 展示标签覆盖、重复行、同一五元组多标签、每类最小样本量；
- 展示同一源 IP/会话跨训练测试的重叠，以及内容完全重复的行；
- 指出“某攻击类在测试集只有 3 条”这类无法支撑结论的情况；
- 支持导出坏样本清单，方便回到原始数据修复。

**验收标准**：

- 标签冲突和低样本类别在运行前可见；
- 报告把数据质量问题和模型性能问题分开描述。

## P1：稳定性和研究深度

### 6. 置信区间与统计显著性

- 对测试集做固定种子的 bootstrap，输出 AUC/PR-AUC/F1 的 95% 区间；
- 同一数据上比较两个模型时给出差值区间，而不是只比较小数点；
- 可选分层/时间块交叉验证，并明确时间序列不能随机分折。

**验收标准**：报告同时展示点估计和区间；区间重叠时不能写“模型 A 优于 B”。

### 7. 特征贡献解释

- 先做 permutation importance（与模型无关），再考虑 SHAP；
- 对 one-hot 编码后的特征映射回原始列；
- 只在用户显式开启时运行，避免大样本训练时间失控。

**验收标准**：输出原始列级别的贡献排序，并能在报告中复算。

### 8. 数据与运行清单

- 为数据集生成 manifest：文件哈希、行数、列数、标签映射、清洗步骤；
- 为运行生成 lock manifest：FlowLab 版本、依赖版本、模型参数、随机种子；
- 支持导出 `flowlab.lock.json`，让报告和产物能对应到具体环境。

**验收标准**：只依赖 manifest 就能判断两份实验是否同数据、同环境、同配置。

### 9. 远程模式的安全边界

**问题**：当前定位是本地单用户工具，没有登录/鉴权；一旦把 `--host 0.0.0.0`
暴露到公网，任何能访问端口的人都能上传文件、读历史、触发训练。

**建议**：

- 默认继续只监听 `127.0.0.1`；
- 远程模式必须显式开启，并提供单用户访问令牌、请求大小上限和反向代理示例；
- 增加登录失败限流、审计日志和可配置的历史访问范围；
- 文档明确“没有多租户隔离，不要直接暴露到公网”。

**验收标准**：未带令牌的远程请求全部 401；默认启动不会监听公网地址。

### 10. 增量 pcap 与批处理

- 支持按时间/文件切片增量读取，避免一次把几十 GB 抓包读进内存；
- 补齐 IPv6、ICMP 类型/代码和 VLAN 过滤，当前 pcap 路径只覆盖 IPv4 + TCP/UDP；
- 输出流分组进度和中间结果，失败后可重新开始；
- 区分“离线实验”和“近实时批量评分”两个入口，不把后者宣传成线速 IDS。

**验收标准**：大 pcap 以固定内存上限运行；批处理结果与一次性读取的结果一致。

### 11. 前端可访问性与国际化

- 抽屉增加焦点陷阱、关闭后焦点回到触发按钮、屏幕阅读器状态播报；
- 图表提供文本摘要和可下载数据，不只依赖颜色；
- 增加界面中英文切换，而不是只提供双语项目介绍；
- 提供键盘导航与至少一轮 axe/人工高对比度检查。

**验收标准**：键盘可以完成配置→运行→查看报告；自动化可访问性检查无严重问题。

## P2：产品化与生态

### 12. 基准数据集复现包

- 为 CICIDS 等公开数据提供下载校验、预处理脚本、固定切分和基线结果；
- 明确数据许可，不把第三方数据或模型权重打进仓库；
- 建立可重复的 benchmark 页面，而不是只在 README 放单个数字。

### 13. 告警调查工作流

- 支持给可疑流打处置状态、备注、关联多个告警；
- 以“源 IP → 时间窗 → 攻击类型 → 处置结论”的方式组织调查，而不是做通用工单系统；
- 导出可脱敏的事件摘要给非算法同事。

### 14. 插件 SDK 与模型卡

- 为插件提供版本约束、输入特征契约和最小测试模板；
- 每个模型记录训练数据范围、适用场景、已知失败模式；
- 发布插件时生成 model card，避免把论文模型包装成“通用检测器”。

### 15. 构建溯源与发布自动化

- 自动生成 SBOM 和构建 provenance；
- Release 同时附 wheel、sdist、校验和与版本变更；
- 对主分支启用依赖更新、CodeQL 或等价的静态安全扫描。

## 明确不做

- 不做线速、串联式 IDS，不替代 Zeek/Suricata；
- 不做通用 SIEM/工单系统；
- 不内置第三方受许可限制的数据集和模型权重；
- 不在默认本地模式下引入账号体系、云同步或遥测上报。

## 推荐顺序

1. 跨实验对比视图；
2. 长任务进度与取消；
3. 阈值扫描与 PR 曲线；
4. 标签质量仪表盘；
5. 历史库迁移与检索；
6. 置信区间与统计显著性。

这六项完成后，FlowLab 会从“能跑一次并出报告”进一步变成“能持续做可比较实验”的研究台。
