# FlowLab 优化路线图

> 目标不是把所有异常检测功能都塞进一个界面，而是让每一次实验更可信、更容易复查、
> 更适合交给别人复现。下面按优先级列出下一步最值得做的事，每项都给出验收标准。

## 当前基线（v0.8.0）

已经完成的能力：

- 统一数据入口：CSV、pcap、Zeek、parquet、NumPy、Excel、JSON 等；
- 数据审计：标签/标识符/目标/端口/时间切分检查，端口泄漏可联动消融；
- 评估：训练/验证/测试三段式、AUC、PR-AUC、F1、精确率、召回率、误报率、混淆矩阵；
- 切分审计：跨集重复行、实体重叠、按 `flow_id` / 五元组 / 源 IP 分组切分；
- 阈值：验证集 F1 自动阈值与测试集阈值扫描；
- 诊断：目标 FPR 阈值、ROC/PR、校准曲线、Brier score；
- 对比：2–4 次历史实验的可比性审计、指标差值与 Markdown 导出；
- 数据质量：标签覆盖、重复行、实体多标签冲突与稀有类别；
- 调查：按攻击类型召回与误报率、典型 FP/FN、源 IP 告警排序；
- 复现：数据指纹、实验指纹、运行环境、种子、切分、阈值来源、特征清单、来源与复现命令；
- 交付：本地 Web、可访问的移动端抽屉、Markdown/HTML/JSON/CSV、wheel、SDist、Docker；
- 历史：SQLite schema v2 原位迁移、检索、筛选、备注、状态、分页、删除与保留数量清理；
- 质量门禁：168 个后端测试、26 个前端测试、Ruff、npm 全量审计、wheel/sdist 与 Docker CI；
- 发布：tag 自动构建、SHA256 校验和、GitHub Release。

以下不再列为“待优化项”，除非出现回归：标签完整性拒绝、时间切分退化标记、
训练集专用预处理、移动端配置/历史/报告三个入口、测试集选模、时间泄漏误放行。

## 方法学底线：在扩功能之前先解决

### A. 测试集只用于最终报告，不参与模型选择（v0.7 已完成）

**现状**：训练 / 验证 / 测试已分离；验证集负责模型选择和 F1 自动阈值，
测试集只在最终报告中评估一次。CLI、API、Web 与两种报告共用同一选择规则。

**建议**：

- 从训练集再切出验证集；模型、阈值和超参数只在验证集上选择；
- 测试集只在最后评估一次，报告中明确写“选择集”和“报告集”；
- 数据不足时使用固定种子的交叉验证，但时间序列必须用时间块/滚动验证；
- `best_model` 改名为“验证集最佳”，同时保留每个模型的测试指标供对照；
- 实验指纹加入选择规则，避免两次实验因选择方式不同却看起来相同。

**仍需补强**：

- 超参数搜索与交叉验证尚未接入；
- 验证集与测试集都要求包含两类样本，小样本数据需要更明确的引导。

### B. 切分时检查重复与实体重叠（v0.7 已完成）

**现状**：切分后检查完全重复内容与实体键重叠；`--split group` 可按
`flow_id`、五元组或源 IP 分组，保证同一实体只落在一个子集。报告明确标注
“未来时间外推 / 未见实体泛化 / 同分布随机泛化”。

**建议**：

- 计算内容重复率，并统计跨训练/测试的重复行；
- 支持按 `flow_id`、五元组或 `src_ip + 时间桶` 分组切分；
- 报告中分别列出“随机行切分”和“按实体分组切分”的结果；
- 对时间切分检查同一长连接是否跨越切分边界。

**仍需补强**：`src_ip + 时间桶` 组合实体、同一长连接跨时间边界检查，
以及 Web 端自定义分组键。

## P0：下一到两个版本

### 1. 跨实验对比视图

**进展（v0.8 已完成）**：Web 与 CLI 共用同一比较结构，支持 2–4 次实验、
数据/特征/切分/验证规模/阈值策略检查、指标差值和 Markdown 导出。

**问题**：现在历史记录只能逐条打开，无法在同一屏比较“修泄漏前/后”或不同阈值。

**建议**：

- 历史列表支持多选 2–4 次实验；
- 先校验数据指纹与特征矩阵是否一致，不一致时明确标红而不是直接比数字；
- 同表展示 AUC、PR-AUC、F1、FPR、召回率、阈值、切分方式、耗时；
- 支持导出对比表为 Markdown，写进论文附录；
- 新增 CLI `flowlab compare` 的同构 JSON 输出，前端与报告共用同一结构。

**验收标准**：

- 两次同数据、不同阈值的实验能在一屏看出 FPR/召回率变化；
- 数据指纹不同的实验会显示不可比警告；
- 对比结果有单元测试与一份可离线打开的 HTML/Markdown 示例。

### 2. 长任务进度与取消

**进展（已完成）**：新增本机单执行位任务队列、阶段进度、协作式取消、
排队状态、任务查询与取消 API；Web 提供实时进度卡、两段式取消确认，并能从
`localStorage` 或活动任务接口恢复刷新前的任务。实验取消或失败不会写历史。

**问题**：69 万行数据上 MLP 可能需要数分钟；当前只有“运行中”，用户不知道进度，
刷新页面也看不到任务是否还在运行。

**建议**：

- 为“读入 → 特征 → 模型 1/N → 消融 → 报告”定义阶段事件；
- API 返回 job id，前端轮询或使用 Server-Sent Events 接收阶段进度；
- 支持取消尚未开始的模型和后续消融；已进入 sklearn 的训练不必强杀线程；
- 离开页面前提示“实验仍在运行”；
- 限制同时运行的任务数，避免上传多个大文件把本机内存打满。

**验收标准**：

- 前端能看到当前阶段、已完成模型数和已用时间；
- 取消后不会写入不完整历史；
- 同一进程内最多运行一个重型实验，第二个任务进入明确排队状态，第三个请求拒绝。

### 3. Web 端无标签评分

**进展（已完成）**：Web 上传入口支持不含 `label` 的文件，用户可选择
`iforest` / `autoencoder`、设置返回条数并后台运行。结果页展示扫描行数、
最高分、Top 中位数与 P95、可疑流排行和 CSV 导出；界面明确标注这不是
评估结果，不计算 AUC/F1，分数不是概率。监督模型会在入队前被拒绝。

**当前边界**：

- 评分结果只保存在当前服务进程，不写入 SQLite 历史；
- 评分与完整实验共用单执行位，会占用同一个本地队列；
- 评分模型尚未支持在 Web 上配置超参数。

### 4. 运行前数据预检与列映射

**进展（已完成）**：新增 `POST /api/preflight` 与 Web 预检面板。训练前会
展示原始列到内部 schema 的映射、列名冲突、可用特征、空值/无限值、时间戳
解析率、标签覆盖，以及训练/验证/测试切分后的类别数量。完整评估的阻断项
与无标签评分的阻断项分别计算；没有标签时仍可直接进入评分。

**当前边界**：预检会完整读取一次文件、计算数据指纹并规划切分，因此大文件
仍需等待读入；预检结果不会持久化，参数变化后会要求重新检查。

### 5. 历史库检索、容量与迁移

**进展（v0.8 已完成界面闭环）**：schema v2、原位迁移、验证指标、模型列表、
实验指纹、搜索、按模型/状态筛选、备注、分页、单条删除、保留数量清理和
数据库体积展示均已完成。

**建议**：

- 为 runs 增加 schema version、experiment fingerprint、模型列表、标签和备注；
- 历史页支持按来源/数据指纹/模型/日期筛选；
- 支持给实验加备注和“基准/失败/已归档”状态；
- 增加配置化的保留策略（按条数或天数），并给出数据库体积；
- 写迁移函数，旧记录读不出来时给出升级提示，而不是让页面报 500。

**验收标准**：

- 旧版数据库能自动迁移或给出可操作提示；
- 搜索 1000 条历史记录仍在 200 ms 内返回；
- 删除和保留策略有测试，不会误删当前打开的实验。

**进展（v0.9 已完成性能与容量收口）**：payload 使用 zlib 压缩，schema v4
记录原始字节数；SQLite 开启 WAL、忙等待、缓存和受控 checkpoint，并为
状态、数据指纹、模型与实验指纹增加索引。历史页改为单连接聚合查询，API
对大响应启用 GZip。200 份合成报告基准确认压缩后约为原始的 23.81%，
历史页查询 p50 为 2.08 ms。

### 6. 阈值扫描、PR 曲线与校准

**进展（v0.8 已完成）**：验证集 F1 / 目标 FPR 自动阈值、测试集阈值扫描、
PR/ROC 曲线、校准曲线、Brier score 与模型参数表均已接入 Web 和报告。

**建议**：

- 对最优模型输出 PR/ROC 曲线和阈值扫描表；
- 允许按目标 FPR 自动选阈值，并记录选择规则；
- 提供 calibration curve 与 Brier score，提醒“分数不是概率”；
- 报告明确区分“排序指标”和“部署阈值”。
- 把当前的 CICIDS 启发式区间做成可配置的数据集画象；未知数据集只提示异常，
  不直接给出“可用/不可用”的强判断。

**验收标准**：

- 用户能在一次运行后看到 10–20 个阈值点的 FPR/召回率；
- 自动阈值会写进复现配置和实验指纹；
- 报告明确指出阈值来自数据驱动还是人工指定。

### 7. 标签质量仪表盘

**进展（v0.8 已完成主要能力）**：标签覆盖、重复行、良性别名归一化、
同一实体多标签冲突、稀有类别和测试集少数类已进入 payload、Web 与报告。
仍可继续补“坏样本清单导出”和原始行定位。

**建议**：

- 展示标签覆盖、重复行、同一五元组多标签、每类最小样本量；
- 展示同一源 IP/会话跨训练测试的重叠，以及内容完全重复的行；
- 指出“某攻击类在测试集只有 3 条”这类无法支撑结论的情况；
- 支持导出坏样本清单，方便回到原始数据修复。

**验收标准**：

- 标签冲突和低样本类别在运行前可见；
- 报告把数据质量问题和模型性能问题分开描述。

## P1：稳定性和研究深度

### 8. 置信区间与统计显著性

- 对测试集做固定种子的 bootstrap，输出 AUC/PR-AUC/F1 的 95% 区间；
- 同一数据上比较两个模型时给出差值区间，而不是只比较小数点；
- 可选分层/时间块交叉验证，并明确时间序列不能随机分折。

**验收标准**：报告同时展示点估计和区间；区间重叠时不能写“模型 A 优于 B”。

### 9. 特征贡献解释

- 先做 permutation importance（与模型无关），再考虑 SHAP；
- 对 one-hot 编码后的特征映射回原始列；
- 只在用户显式开启时运行，避免大样本训练时间失控。

**验收标准**：输出原始列级别的贡献排序，并能在报告中复算。

### 10. 数据与运行清单

**进展（v0.8 已完成运行环境部分）**：报告记录 FlowLab/Python/pandas/NumPy/
scikit-learn 版本，环境进入实验指纹。数据集 manifest 可继续扩展为独立文件。

- 为数据集生成 manifest：文件哈希、行数、列数、标签映射、清洗步骤；
- 为运行生成 lock manifest：FlowLab 版本、依赖版本、模型参数、随机种子；
- 支持导出 `flowlab.lock.json`，让报告和产物能对应到具体环境。

**验收标准**：只依赖 manifest 就能判断两份实验是否同数据、同环境、同配置。

### 11. 远程模式的安全边界

**问题**：当前定位是本地单用户工具，没有登录/鉴权；一旦把 `--host 0.0.0.0`
暴露到公网，任何能访问端口的人都能上传文件、读历史、触发训练。

**建议**：

- 默认继续只监听 `127.0.0.1`；
- 远程模式必须显式开启，并提供单用户访问令牌、请求大小上限和反向代理示例；
- 增加登录失败限流、审计日志和可配置的历史访问范围；
- 文档明确“没有多租户隔离，不要直接暴露到公网”。

**验收标准**：未带令牌的远程请求全部 401；默认启动不会监听公网地址。

### 12. 增量 pcap 与批处理

- 支持按时间/文件切片增量读取，避免一次把几十 GB 抓包读进内存；
- 补齐 IPv6、ICMP 类型/代码和 VLAN 过滤，当前 pcap 路径只覆盖 IPv4 + TCP/UDP；
- 输出流分组进度和中间结果，失败后可重新开始；
- 区分“离线实验”和“近实时批量评分”两个入口，不把后者宣传成线速 IDS。

**验收标准**：大 pcap 以固定内存上限运行；批处理结果与一次性读取的结果一致。

### 13. 前端可访问性与国际化

- 抽屉增加焦点陷阱、关闭后焦点回到触发按钮、屏幕阅读器状态播报；
- 图表提供文本摘要和可下载数据，不只依赖颜色；
- 增加界面中英文切换，而不是只提供双语项目介绍；
- 提供键盘导航与至少一轮 axe/人工高对比度检查。

**验收标准**：键盘可以完成配置→运行→查看报告；自动化可访问性检查无严重问题。

## P2：产品化与生态

### 14. 基准数据集复现包

- 为 CICIDS 等公开数据提供下载校验、预处理脚本、固定切分和基线结果；
- 明确数据许可，不把第三方数据或模型权重打进仓库；
- 建立可重复的 benchmark 页面，而不是只在 README 放单个数字。

### 15. 告警调查工作流

- 支持给可疑流打处置状态、备注、关联多个告警；
- 以“源 IP → 时间窗 → 攻击类型 → 处置结论”的方式组织调查，而不是做通用工单系统；
- 导出可脱敏的事件摘要给非算法同事。

### 16. 插件 SDK 与模型卡

- 为插件提供版本约束、输入特征契约和最小测试模板；
- 每个模型记录训练数据范围、适用场景、已知失败模式；
- 发布插件时生成 model card，避免把论文模型包装成“通用检测器”。

### 17. 构建溯源与发布自动化

**进展**：tag 发布工作流已附 wheel、sdist、依赖清单、SHA256 与自动 Release notes；
Dependabot 已启用。SBOM、构建 provenance 与 CodeQL 仍可继续补。

## 明确不做

- 不做线速、串联式 IDS，不替代 Zeek/Suricata；
- 不做通用 SIEM/工单系统；
- 不内置第三方受许可限制的数据集和模型权重；
- 不在默认本地模式下引入账号体系、云同步或遥测上报。

## 推荐顺序

1. 历史 payload 体积治理与查询性能；
2. 置信区间与统计显著性；
3. 原始列级特征贡献（permutation importance）；
4. 公开数据集/pcap 固定 CI 与可复现基准页。

跨实验对比、历史检索/容量管理、标签质量、诊断曲线和运行环境已在 v0.8
形成闭环；下一阶段重点从“结果可信”转向“长任务可操作、无标签也可用、
数据接入前可预检”。
