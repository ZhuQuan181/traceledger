## 一、一句话结论

功能已经超出 MVP，但产品有两个真空地带：**"研究者的前 30 分钟"** 和 **"需求验证"**。
现在的状态是「一个能跑得很好的内部工具」，还不是「别人拿到就能复现的产品」。

## 三、首次使用的断点（真人会卡住的地方）

1. **装环境**：README 直接 `uv sync`，没写 uv 怎么装。非 Python 用户第一步就断。
2. **没有示例数据**：合成数据能证明"流程通"，证明不了"你的数据能跑"。研究者第一件事是拖自己的 CSV。
3. **CICIDS 真实规模未验证**：只跑过千级样本；69 万行 + 78 列的行为（内存、one-hot 维度、耗时）没有数据点。
4. **报告不能自证特征集合**：别人拿到报告，不知道模型吃了哪些列，无法复现。
5. **失败恢复**：tshark / pyarrow / pickle 都有明确提示（这块做得好），但**没有"下一步该点哪"的链接**。

## 六、明确不该做的（防止范围膨胀）

- 实时抓包 / 线速：与"研究者工作台"定位冲突，做了会被当成 IDS 评判
- 规则引擎 / SIEM 对接：这是 Suricata + Wazuh 的地盘
- 多租户 / 云服务：本地优先是信任基础
- 自动调参 / AutoML：会把"可解释"变成黑箱
